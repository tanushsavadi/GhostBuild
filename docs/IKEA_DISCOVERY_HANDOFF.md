## 6. Design decisions already made (keep unless you find a reason)
- Discovery is deterministic everywhere except the optional live search; no LLM on selection/gesture/ranking. The model only proposes URLs; shown facts come from the validated official page.
- Honest labelling: cached = "read from ikea.com on <verified date>"; live = "live official-site search"; exact lookup = "read from ikea.com just now" or "saved record, read <date>". Attributes the page never mentions are "unverified", not "absent". "Manual verified" only after the PDF HEAD check.
- Step N in the card equals manual step N (no extra prep step) so "show me step 14" = index 13. Parts-overview pages are not steps; the parts intent and `how` views serve "which fastener".
- Configuration key is the option id (`left`/`right`); per-article remembered config is stored; the assistant brain's step context should state product + configuration (extend `assistant/prompts.step_context`, keep it device-agnostic for lint).
- Left/right means as seen from the sitter's side, matching how the manual's page-10 pictures are drawn; always show the manual's own inset pictures next to the question so the person can verify.

## 7. Gotchas
- `UrllibFetcher` only allows ikea.com product/asset URLs and checks redirects; keep the allow-list. Product page is ~1.1 MB; 0.9 s typical.
- `rank()` drops candidates whose shop `typeName` is a different category; `COMPAT` lets desk/table interchange. Count-mismatch ("two drawers" vs page says one) is a conflict (-3), not removal.
- Search results order is the provider's relevance and is only a tie-breaker.
- The earlier Codex IKEA "previous task" the user mentioned does not exist in this repo or any session (only a queued voice request file `knowledge/requests/20261018T085157Z-1.json` saying "Build me my IKEA sofa."); everything above was built here from the real IKEA page and PDF.
- Welcome screen/first-run flow changed earlier in the sprint (no BUILD/FIX question); keep it. A goal typed on the phone is `via="phone_text"`, spoken is `via="voice"`; both reach `Runtime.resolve_goal`.
- `Menu.options` is 2-4 strings; `Menu.prompt` <= 24 chars; `Cue` 24/26; `ImageRef.title` <= 24.
- Playbook guard: a swipe-down within 600 ms of a step frame is ignored; spoken "done" bypasses it on purpose (`from_ask=True`).
